# Framework Evolution｜方法如何产生、发布与更新

> 面向维护者和贡献者的通用发布协议。本仓库只保存公共方法，不收集使用者的私人 SecondMe 档案。

## 循环原则

```text
使用者在各自的私人空间探索与实践
                 ↓
发现可能适用于更多人的方法问题
                 ↓
整理为不依赖任何真实私人案例的通用规则
                 ↓
验证适用范围、反例、来源、版权与隐私
                 ↓
明确批准公开后，独立撰写公共稿
                 ↓
发布新的 SecondMe Framework 版本
                 ↓
使用者收到可选择、需审核的更新 PR
                 ↓
使用者决定是否采纳，私人模型保持独立
```

**不接受个人资料自动上传、自动公开或未经审核的个案改写。**

## 合格的公共贡献

- 定义可复用的问题与方法步骤；
- 用完全虚构的独立情境演示；
- 清楚指出适用与不适用场景；
- 区分理论引用、作者解释、模型推断和用户本人明确的价值；
- 保留反证条件和用户更正权；
- 使用适当的科学表述，不宣称未经验证的临床效度。

## 不应公开的材料

- 私人原始对话、关系史、心理健康记录、梦境、身份与定位信息；
- 即使删除姓名仍可凭罕见事件、时间或表达风格识别的人物案例；
- 用户私人仓库的文件路径、历史提交或私人 Git 关联；
- 未获授权的第三方数据或受限制的学术内容；
- 用户不知情、未同意的自动收集与反馈记录。

## 公共发布门槛

1. **通用性检查**：完全不知道发现者是谁，也能理解和应用吗？
2. **独立性检查**：没有引用、改写、重新排序私人聊天或真实案例吗？
3. **理论来源检查**：有没有把假说写成定论，或把引用当作认可？
4. **反证检查**：何时会错？哪些新材料能推翻判断？
5. **隐私检查**：源文件、例子、文件名、图形元数据、提交作者、历史与 PR 讨论是否都已复核？
6. **用户控制检查**：是否允许拒绝、删除、暂停、不更新？
7. **发布确认**：作者已明确选择公开这份**独立公共文档**。

此处的检查不是自动隐私证明，而是人工审查流程；机器扫描只能提供部分辅助证据。

## 版本发布与已有用户同步

官方可自动更新的内容仅限 `framework/`、`prompts/`、`templates/` 中的 Markdown 文件。

发布这些文件的新版时：
- 维护者递增 `.secondme/framework-manifest.json` 的语义版本并更新官方 Git Blob SHA；
- 运行离线测试与差异审查；
- 检查没有私人信息并正常发布；
- 用户私人仓库根据自己的 `framework-lock.json` 判断能否自动应用；
- 改过的文件跳过；官方删除不自动删用户副本；更新需要用户审核 PR。

**关键限制：** `scripts/`、GitHub Actions 和数据库升级代码不会由现有自动更新器执行或安装。此类可执行功能需额外的、明确授权的迁移路径。参见 [更新器说明](UPDATES.md)。

## 两个方向不可混淆

**私人探索 → 公开框架：** 必须是显式、独立编写并审核的“知识提升”，不能做 Git 自动同步。

**公开框架 → 私人副本：** 是经过白名单、版本指纹校验和本人合并的“方法更新”，不修改个人记录与结论。

> 开放方法；私有生活；让不同人的 SecondMe 都拥有独立的未来。
